# P0 核心流程产品说明（节点清单 · 状态机）

> 版本：v1.0｜角色：产品说明（研发/运营/商务共用）  
> 业务边界：**全国景区及文旅资源**（门票、住宿、演艺、餐饮、交通、汉服/研学体验等）；汉服节为**流量与活动样板**，某一目的地（如敦煌、桂林）仅为**资源接入样例**，非系统专属对象。  
> 范围：仅 P0 四张主流程；B 端赞助展位、复杂风控、模板工厂等见后续版本。

---

## 0. 统一对象模型（四张图共用）

| 对象 | 说明 | 全国化约定 |
|------|------|------------|
| 目的地 Destination | 城市/景区集群（如某市文旅、某风景区管委会） | 多目的地并存，数据按目的地隔离 + 平台统一用户 |
| 资源 Resource | 可售履约单元的原料：景点、酒店、演出、体验点等 | 类型枚举可扩展，不写死某一景区 |
| 产品 Product / SKU | 对外可售：单票、联票、过夜包、活动票、权益包 | 可跨资源组合；可挂「活动」或「目的地」 |
| 活动 Campaign | 汉服节主会场/分会场/主题周等限时经营容器 | 与目的地解耦；活动可预售多个目的地产品 |
| 用户 User | 同一身份贯穿宣传→购票→核销→加购→转化 | 一号通吃全国资源 |
| 票证 Ticket | 可核销凭证（一单一证或多证） | 状态机全国统一 |
| 权益 Entitlement | 同袍徽章/电子权益，可兑换指定资源优惠 | 规则按「适用目的地/资源范围」配置 |
| 库存 Inventory | 日库存、场次库存、配额、保留房等 | 渠道配额与门市库存分离 |
| 结算单 Settlement | 按核销或按约定规则生成的应付/应收 | 按**资源方/目的地**分账，非按活动一刀切 |

**核心原则**

1. 能在大盘完成的，不再外挂第二套报名/验票工具。  
2. 活动中台能力与景区中台能力共用同一套订单/票证/核销状态，只换「场景配置」。  
3. 全国复制 = 换目的地与资源配置，不换状态机。

## 1. 流程一：活动/目的地经营总闭环

### 1.1 目标

用一张图定义「从流量到过夜再到复购」的经营主路径；汉服节与全国景区套票走同一闭环，差异仅在入口物料与 SKU 配置。

### 1.2 角色

| 角色 | 职责 |
|------|------|
| 游客/同袍 C | 发现、购买、核销、加购、领取权益 |
| 运营 Ops | 配置活动/产品、内容投放、会后转化 |
| 资源方 Partner | 提供渠道价与配额、现场履约协同 |
| 场地方/景区 Venue | 容量与通行规则、核销点管理 |
| 系统 Platform | 统一入口、库存、订单、票证、用户、看板 |

### 1.3 节点清单（主路径）

| 序号 | 节点 | 输入 | 输出 | 系统落点 |
|------|------|------|------|----------|
| A1 | 内容触达 | 公域种草/社群/官方背书 | 点击进入唯一活动页或目的地产品页 | 归因参数 → 用户会话 |
| A2 | 浏览决策 | 日程/地图/SKU/须知 | 加购意向 | 浏览/曝光日志 |
| A3 | 下单支付 | 选 SKU、人数、出行日 | 待支付订单 | Order=`CREATED` |
| A4 | 支付成功 | 支付回调 | 订单已付、占库存确认 | Order=`PAID` |
| A5 | 出票/发证 | 履约规则 | 电子票码 / 权益写入 | Ticket=`ISSUED`；可选 Entitlement=`ACTIVE` |
| A6 | 行前触达 | 须知、动线、改期入口 | 到场准备 | 消息/站内信 |
| A7 | 入园/到店核销 | 扫码 | 核销成功、人流计数 | Ticket=`USED` |
| A8 | 现场加购 | 租赁/摄影/文创/二次票 | 新订单或子单 | 同一 User 下新 Order |
| A9 | 私域沉淀 | 核销/加购完成 | 用户标签、可运营名单 | User Profile / 标签 |
| A10 | 会后/跨地转化 | 运营任务、徽章可用范围 | 目的地过夜包/联票订单 | 新 Order（可跨 Destination） |
| A11 | 复盘 | 销售/入园/转化漏斗 | 运营与商务决策 | 看板指标 |

### 1.4 分支与异常（总闭环层）

| 分支 | 触发 | 处理要点 |
|------|------|----------|
| 多入口分流 | 外链未回唯一页 | 产品禁配；投放只允许带参深链 |
| 支付成功未出票 | 回调成功、出票失败 | 自动重试 → 工单；订单=`FULFILLING` |
| 未核销过期 | 过出行日/有效期 | Ticket=`EXPIRED`；按退改规则是否退款 |
| 配额售罄 | 渠道配额用尽 | 停售该渠道 SKU；可引导其他日期/资源 |
| 跨目的地转化失败 | 权益范围不含该资源 | 前端不可选；服务端二次校验 |

### 1.5 状态机（经营会话，可选埋点对象）

用于运营看板「用户处于哪一段」，非强事务对象：

```
ANONYMOUS → LANDED → BROWSING → ORDERING → PAID_HOLDING_TICKET
    → ARRIVED_VERIFIED → ADDON_CONSUMED → RETARGETABLE → CONVERTED_DESTINATION
```

| 状态 | 含义 |
|------|------|
| ANONYMOUS | 未登录或未识别 |
| LANDED | 进入活动/产品页 |
| BROWSING | 有有效浏览 |
| ORDERING | 有未完成订单 |
| PAID_HOLDING_TICKET | 已购未核销 |
| ARRIVED_VERIFIED | 至少一证核销 |
| ADDON_CONSUMED | 有现场或会后加购 |
| RETARGETABLE | 进入可运营池 |
| CONVERTED_DESTINATION | 产生跨资源/跨目的地转化订单 |

## 2. 流程二：C 端交易履约（购票 · 出票 · 退改）

### 2.1 目标

全国统一「可卖、可付、可出、可退、可核」的交易履约；支持活动票、景区单票、联票、过夜包（票+房等组合）等 SKU 形态。

### 2.2 角色

游客 C、支付渠道、库存服务、履约（出票）服务、客服/运营、资源方（确认保留房/场次时）。

### 2.3 节点清单

| 序号 | 节点 | 规则要点 | 系统落点 |
|------|------|----------|----------|
| B1 | 选品 | SKU 类型：`ACTIVITY` / `SCENIC` / `COMBO` / `PACKAGE` / `ENTITLEMENT_BUNDLE` | Product 快照写入订单 |
| B2 | 校验可售 | 上下架、出行日、配额、实名要求、年龄/限购 | 失败则不可提交 |
| B3 | 创建订单 | 金额、优惠、渠道码、目的地/活动归属 | Order=`CREATED`；库存=`HOLD` |
| B4 | 拉起支付 | 超时未付释放 HOLD | 支付中 |
| B5 | 支付结果 | 成功 / 失败 / 关单 | Order=`PAID` / `CLOSED` |
| B6 | 履约拆单 | PACKAGE 拆为票证行 + 住宿行等 | Fulfillment Line |
| B7 | 出票发码 | 一码一证或多证；联票可多资源共用规则 | Ticket=`ISSUED` |
| B8 | 行前变更 | 改期/改人（若政策允许） | 校验库存后改快照 |
| B9 | 退款申请 | 未核销/部分核销策略 | Refund=`APPLYING` |
| B10 | 退款完成 | 释放剩余库存、作废未用票 | Ticket=`REFUNDED`；Order=`REFUNDED`/`PARTIAL_REFUNDED` |

### 2.4 订单状态机 `Order.status`

```
CREATED ──支付成功──► PAID ──出票中──► FULFILLING ──全部履约凭证就绪──► FULFILLED
   │                      │                │
   │超时/取消             │支付后关单失败   │部分失败 → 人工/重试
   ▼                      │                │
 CLOSED                   │                ▼
                          └──────────► CLOSED（极少：支付成功但业务关单，需对账）

FULFILLED ──整单退──► REFUNDED
         └──部分退──► PARTIAL_REFUNDED
         └──全部票证用完──► COMPLETED（可选，与 FULFILLED 合并亦可）
```

| 状态 | 允许操作 |
|------|----------|
| CREATED | 支付、取消 |
| PAID | 出票、支付成功退（特殊） |
| FULFILLING | 重试出票、客服介入 |
| FULFILLED | 退改（政策内）、核销 |
| PARTIAL_REFUNDED | 剩余票继续核销或再退 |
| REFUNDED | 终态 |
| COMPLETED | 终态（可选） |
| CLOSED | 终态（未支付关闭） |

### 2.5 库存状态机 `InventoryLot`（按日/场次/配额维度）

```
OPEN ──预占 HOLD──► HELD ──支付确认──► SOLD
  ▲                  │
  └────超时释放──────┘
OPEN ──运营停售──► CLOSED
SOLD ──退款回滚──► OPEN（回到可售，受规则限制）
```

**全国渠道配额**：同一资源可有 `quota_channel`（平台渠道）与 `quota_public`；售卖只扣对应配额。旺季有月度上限时，用配额对象而非改价格状态。

### 2.6 票证状态机 `Ticket.status`（与流程三共用）

见第 3 章；交易侧负责：`ISSUED` / `REFUNDED` / `EXPIRED` / `VOID`。

### 2.7 组合产品（过夜包 / 联票）约定

| SKU 类型 | 履约拆分 | 失败策略（P0 建议） |
|----------|----------|---------------------|
| 联票 COMBO | 多 Ticket，可分资源核销 | 一资源不可约则整单不可售（P0）；P1 再做部分可售 |
| 过夜包 PACKAGE | 票 + 房晚（或券）等多履约行 | 房确认失败 → 整单履约失败进入人工或自动退 |
| 活动票 ACTIVITY | 单证或多分区证 | 按场地方分区权限配置 |

## 3. 流程三：入园/到店核销与通行

### 3.1 目标

活动现场闸机与全国景区手持/闸机核销**共用票证状态机**；差异配置在「核销点、票种权限、重入规则、是否需预约号」。

### 3.2 角色

游客、核销员、场地方管理员、系统（含离线缓存）。

### 3.3 节点清单

| 序号 | 节点 | 说明 | 系统落点 |
|------|------|------|----------|
| C1 | 出示凭证 | 电子码 / 证件辅助查票 | 出示 Ticket |
| C2 | 扫码解析 | 校验签名、防伪、归属商户 | 解析 ticket_id |
| C3 | 规则引擎 | 票种、日期、分区、重入、黑名单、预约号 | Pass / Deny + 原因码 |
| C4 | 核销记账 | 写核销流水、回写票状态、计数 | Ticket→`USED`；日志 |
| C5 | 通行放行 | 闸机开 / 手持确认 | 现场反馈 |
| C6 | 异常处理 | 补录、改签后重验、一码多刷拦截 | 工单或授权核销 |
| C7 | 离线同步 | 弱网先本地判，恢复后上传 | 冲突检测 |

### 3.4 票证状态机 `Ticket.status`（权威）

```
                  ┌── 退款成功 ──► REFUNDED（终态）
                  │
ISSUED ──核销成功──► USED（终态，默认不可再核；若允许当日重入见下）
  │
  ├── 过有效期 ──► EXPIRED（终态）
  ├── 运营作废 ──► VOID（终态）
  └── 挂失/冻结 ──► FROZEN ──解冻──► ISSUED
```

**当日重入（配置项，非新状态）**

- 策略 A：`USED` 后同核销点当日凭同一码放行，只记「重入流水」，状态仍为 `USED`。  
- 策略 B：首次核销为 `USED`，重入需「重入授权码」（人工）。  
P0 建议活动现场用 A，文物类强预约景区用 B 或禁止重入。

### 3.5 单次核销流水 `VerifyRecord.status`

```
PENDING → SUCCESS
       → DENIED（原因码）
       → PENDING_SYNC（离线已放行待同步）
       → CONFLICT（同步时发现重复/已退）→ 人工
```

| 原因码（示例） | 含义 |
|----------------|------|
| NOT_FOUND | 码无效 |
| WRONG_DATE | 日期不符 |
| WRONG_VENUE | 核销点无权 |
| ALREADY_USED | 已核销且不允许重入 |
| EXPIRED / REFUNDED / VOID / FROZEN | 状态不允许 |
| QUOTA_BLOCK / BLACKLIST | 风控或名单 |
| NEED_RESERVATION | 缺预约号（如部分石窟/博物馆） |

### 3.6 核销点配置（全国化）

每个 `VerifyGate` 绑定：`destination_id`、可核销 `product_type`/`ticket_type`、分区、是否离线、重入策略。  
汉服节主入口/贵宾口/演职口 = 多个 Gate；全国景区闸机同理。

## 4. 流程四：权益（同袍徽章等）+ 渠道结算

### 4.1 目标

把「节庆热闹」变成**全国可配置的资源优惠与可对账成本**：徽章是权益容器，适用哪些目的地/资源由规则引擎配置，不写死单一景区。

### 4.2 角色

游客、运营（发证规则）、资源方（认渠道优惠）、财务、系统。

### 4.3 权益子流程节点

| 序号 | 节点 | 说明 | 系统落点 |
|------|------|------|----------|
| D1 | 发证 | 购票赠送 / 现场领取 / 活动任务达成 | Entitlement=`ACTIVE` |
| D2 | 绑定用户 | 必须绑定平台 User | 防转卖策略可配置 |
| D3 | 规则匹配 | 用户选目的地产品时计算可用优惠 | 优惠明细进订单 |
| D4 | 下单占用 | 权益与订单绑定 | Entitlement=`LOCKED`（可选） |
| D5 | 到店核销优惠 | 随票核销或单独验权益 | 核销流水带 entitlement_id |
| D6 | 核销完成 | 次数型权益扣减；到期失效 | `CONSUMED` / 次数-1 / `EXPIRED` |
| D7 | 生成结算 | 按「门市价−渠道价」或约定结算价 | Settlement Line |

### 4.4 权益状态机 `Entitlement.status`

```
INACTIVE（未激活）──激活──► ACTIVE
ACTIVE ──下单锁定──► LOCKED ──支付失败/取消──► ACTIVE
LOCKED ──履约成功──► ACTIVE 或 CONSUMED（按「次数/一次性」）
ACTIVE ──用尽──► CONSUMED
ACTIVE ──过期──► EXPIRED
任意非终态 ──作废──► REVOKED
```

| 状态 | 含义 |
|------|------|
| INACTIVE | 已生成未生效（未绑用户等） |
| ACTIVE | 可用 |
| LOCKED | 已被某订单预占 |
| CONSUMED | 已用尽（终态） |
| EXPIRED | 过期（终态） |
| REVOKED | 作废（终态） |

**规则对象 `EntitlementRule`（全国配置）**

- 适用范围：`destination_ids[]` / `resource_ids[]` / `product_tags[]`  
- 优惠形态：立减、折扣、换购、赠体验时长  
- 次数：一次 / N 次 / 期内不限（慎用）  
- 有效期：绝对日期或自激活起 N 天  
- 与渠道价关系：权益优惠**不得突破**与资源方协议底价（服务端强校验）

### 4.5 结算子流程节点

| 序号 | 节点 | 说明 | 系统落点 |
|------|------|------|----------|
| E1 | 计费触发 | 默认：**核销成功**记一笔应付；预付模式可配置 | 应计事件 |
| E2 | 计价 | 协议结算价 × 数量 − 调整项 | Settlement Line=`PENDING` |
| E3 | 账期汇总 | 按资源方 + 账期出账单 | Bill=`DRAFT` |
| E4 | 对账确认 | 双方确认差异 | Bill=`CONFIRMED` |
| E5 | 付款/开票 | 财务执行 | Bill=`SETTLED` |
| E6 | 差异单 | 重复核销、离线冲突、部分退 | Adjustment |

### 4.6 结算单状态机 `SettlementBill.status`

```
DRAFT ──提交对账──► PENDING_CONFIRM ──双方确认──► CONFIRMED ──付款完成──► SETTLED
         │                    │
         │                    └──差异──► DISPUTED ──调整后──► PENDING_CONFIRM
         └──作废──► VOID
```

| 行项目类型 | 示例 |
|------------|------|
| TICKET_VERIFY | 门票/联票核销结算 |
| ROOM_NIGHT | 间夜结算 |
| SHOW | 演出核销结算 |
| ENTITLEMENT_DISCOUNT | 徽章优惠导致的渠道补差（若协议约定） |
| ADJUSTMENT | 退款冲正、补差 |

**P0 结算原则（全国）**

1. 一笔核销流水最多对应一笔有效结算行（冲正用红字调整）。  
2. 结算主体是**资源方/合同主体**，不是「活动名字」。  
3. 汉服节只影响「哪个 Campaign 带来的订单」归因字段，不改变结算状态机。

### 4.7 权益与交易的衔接（防资损）

```
选品计价时：
  若 entitlement 适用 → 展示优惠价
  提交订单 → LOCKED
  支付失败 → 解锁回 ACTIVE
  出票成功 → 按规则 CONSUMED 或保留次数
  整单退款且未核销 → 权益回滚 ACTIVE（若仍在有效期）
  已核销后退款 → 权益不回滚；结算行冲正
```

## 5. 四张流程的衔接关系

```
[流程一 总闭环]
    │
    ├─下单支付/出票────────► [流程二 交易履约]
    │                              │
    ├─到场核销──────────────► [流程三 核销] ◄── Ticket 状态权威
    │                              │
    └─徽章/渠道优惠────────► [流程四 权益] ──核销成功──► [流程四 结算]
```

**共享主键建议**

`user_id` · `order_id` · `ticket_id` · `entitlement_id` · `verify_record_id` · `destination_id` · `partner_id` · `campaign_id(nullable)`

## 6. P0 验收标准（产品可用定义）

| 编号 | 验收项 |
|------|--------|
| AC1 | 任意两个目的地资源配置后，不改代码即可上架 SKU 并完成购票→核销 |
| AC2 | 同一用户可先买活动票，再凭权益购买另一目的地产品，身份不断号 |
| AC3 | 票证状态机在活动闸机与景区手持核销行为一致（仅 Gate 配置不同） |
| AC4 | 支付成功必达出票或进入可补偿的 FULFILLING；禁止「已扣款无凭证」静默失败 |
| AC5 | 核销成功可生成对应资源方的结算草稿行；退款可冲正 |
| AC6 | 外链投放仅进入配置的唯一活动/产品页（带归因） |

## 7. 明确不在 P0 的内容

- 赞助冠名/展位销售完整权益包  
- 多级分销员体系  
- 文物类预约号与官方票务系统的深度 API（可先人工协助预约，状态预留 `NEED_RESERVATION`）  
- 智能定价、动态折扣引擎  
- 目的地「一键复制」模板工厂（可先运营后台手工配置）
