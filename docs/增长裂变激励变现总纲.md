## 0. 先纠正定位

### 0.1 这个项目到底是什么

**不是**文旅售票平台，**不是**汉服社区产品，**不是**某一次线下活动的报名工具。

**是一套可复用的互联网增长机器：**

```text
打开 App / 小程序
  → 做任务（签到、步数、组队、答题、浏览、看广告）
  → 得积分（活力值）
  → 抽奖 / 兑换低成本实物礼品
  → 邀请好友、分享海报获得更多机会
  → 商城用「现金 + 积分」消费
  → 广告 / 商品毛利 / 品牌合作回本
```

汉服节、景区、某个主题活动，只是这台机器上**可插拔的主题皮肤与奖池素材**。主题下周可以换，机制不能换。

### 0.2 对什么负责

产品与运营的一切决策，只对下面四个结果负责：

| 指标 | 含义 | 为什么是核心 |
|------|------|--------------|
| **DAU** | 日活跃用户 | 没有打开就没有广告、没有任务完成、没有转化 |
| **传播率（K 因子）** | 每个老用户带来多少有效新用户 | 决定获客成本能否低于激励成本 |
| **转化率** | 活跃 → 抽奖/兑换/下单/看广告 | 决定积分有没有变成生意 |
| **贡献毛利** | 收入 − 礼品 − 运费 − 支付 − 售后 − 投流 | 决定能不能长期经营 |

注册量、PV、虚高 GMV **不是**北极星。

### 0.3 一句话总纲

> **用低成本即时激励拉动每日打开；用邀请、组队、分享拉动传播；用抽奖与礼品制造期待；用现金+积分商城和广告把注意力变现；主题活动只负责换皮获客，不绑定业务生死。**

## 1. 核心用户逻辑（去掉行业标签）

### 1.1 用户为什么留下来

年轻人留下来通常只因为四件事：

1. **今天打开有收获**（签到、步数、小礼品进度）  
2. **差一点就能得到**（差 1 人组队、差 20 分兑换、差 1 次抽奖）  
3. **有东西可晒**（中奖、连续签到、队伍排名）  
4. **礼品/商品是我喜欢的**（颜值、实用、低价、可送人）

因此货盘与奖池要围绕「年轻用户喜欢的低客单商品」，而不是景区票。

### 1.2 用户分层（通用）

| 层级 | 定义 | 目标动作 |
|------|------|----------|
| 新客 | 0–3 日 | 完成首签、首任务、理解「做任务能得礼」 |
| 活跃 | 近 7 日 ≥3 天打开 | 每日任务、抽奖、组队 |
| 传播者 | 有有效邀请或高分享 | 给更高抽奖权重/限定礼 |
| 消费者 | 产生现金订单或高广告价值 | 积分抵扣、复购券 |
| 羊毛/风险 | 刷设备、刷邀请、只兑不活跃 | 延迟结算、降权、限制大奖 |

## 2. 机制设计总览

### 2.1 五大引擎

| 引擎 | 用户行为 | 系统产出 | 商业作用 |
|------|----------|----------|----------|
| **打开引擎** | 签到、推送、连续奖励 | DAU | 广告与任务基数 |
| **任务引擎** | 步数、浏览、答题、看视频、组队 | 积分发放 | 行为结构化 |
| **裂变引擎** | 邀请、分享、组队满员 | 有效新增 | 降低 CAC |
| **激励引擎** | 抽奖、兑换、排行榜 | 礼品履约 | 刺激回流与传播 |
| **变现引擎** | 商城下单、广告完播、品牌任务 | 现金收入 | 回本 |

主题活动（汉服节/校园周/春节等）= 临时把奖池和海报换皮，不改五大引擎。

### 2.2 用户主路径（必须做短）

```text
进入首页
 → 一眼看到：今日还能得什么 / 差多少兑礼 / 抽奖剩余次数
 → 一键完成 1–3 个今日任务
 → 积分到账动画
 → 引导：抽一次 / 去兑礼 / 邀好友加速
 → 中奖或进度更新 → 生成分享卡
```

超过 3 步才看到奖励 = 失败设计。

## 3. 打开与任务机制（为 DAU 负责）

### 3.1 每日打开理由（固定结构）

首页固定四大模块（主题可换文案，结构不变）：

1. **今日奖励进度**：连续签到第 N 天、今日还可领 X 分  
2. **今日任务清单**（≤3 个主任务）  
3. **礼品墙/抽奖入口**：库存、倒计时、差多少分  
4. **邀请/组队入口**：差几人、双方各得什么  

### 3.2 签到

采用 **7 日循环**，避免无限膨胀：

| 天数 | 积分 | 额外 |
|------|------|------|
| 1 | 5 | — |
| 2 | 6 | — |
| 3 | 8 | — |
| 4 | 10 | — |
| 5 | 12 | 抽奖 +1 |
| 6 | 15 | — |
| 7 | 20 | 限定抽奖码或小礼品进度 |

规则：

- 断签清零当前循环（可每月付少量积分补签 1–2 次）  
- 第 7 天必须有「可感知奖励」，但不能是高成本实物必得  
- 签到本身不强制分享  

### 3.3 日常任务池（后台可配置）

| 任务类型 | 示例 | 积分 | 日上限 | 备注 |
|----------|------|------|--------|------|
| 打开类 | 每日签到 | 5–20 | 1 | 基础 DAU |
| 行为类 | 有效浏览内容 N 秒 | 3–5 | 2 | 防秒退 |
| 健康类 | 步数 3k/6k/1w | 3/5/8 | 取最高一档 | 需授权验签 |
| 互动类 | 答题、点赞、收藏 | 5 | 1–2 | 题库可换主题 |
| 广告类 | 激励视频（可选） | 8–12 | 1–2 | 非强制；有流量再开 |
| 社交类 | 组队打卡、助力好友 | 10–20 | 有上限 | 服务裂变 |
| 消费类 | 浏览商城/加购/下单 | 5–下单返积分 | 有上限 | 服务转化 |

**硬规则：**

- 每日主任务不超过 3 个，可选任务不超过 2 个  
- 任务奖励全部后台配置，禁止客户端写死  
- 「看广告」永远不能成为唯一获得积分方式  

### 3.4 组队 / 队伍玩法（提高打开与传播）

推荐做一个常驻轻量玩法：**「今日小队」**

- 2–5 人成队  
- 全队今日总步数 / 总任务分达标 → 全队加分或共享抽奖次数  
- 队内有人未打开 → 系统提示「差 1 人打开即可领奖」  
- 周榜：队伍积分排行，周奖励以低成本礼品或抽奖码为主  

目的：用社交压力提高次日打开，而不是用现金。

### 3.5 新手 3 分钟激活

新用户第一次进来只做三件事：

1. 领「新手礼包积分」  
2. 完成 1 个超简单任务（签到或浏览）  
3. 看到「再做 X 就能抽/兑」的明确目标  

不要一上来问卷、会员、复杂社区。

## 4. 裂变机制（为传播率负责）

### 4.1 有效新增定义（奖励结算唯一标准）

邀请奖励只认 **有效新增**，同时满足：

1. 通过邀请码/海报/链接首次进入  
2. 完成平台要求的基础授权  
3. 完成至少 1 个非分享类任务  
4. 未命中设备 / IP / 频率黑名单  
5. 奖励先 **冻结 24 小时** 再发放  

K 因子公式：

```text
K = 人均成功邀请有效新用户数 × 新用户次日留存率
```

目标：冷启动期 K ≥ 0.3；健康期冲击 0.8–1.2。  
K < 0.2 时，禁止加码高成本礼品拉裂变。

### 4.2 邀请阶梯（确定性 + 抽奖，控制成本）

| 有效邀请数 | 奖励 | 成本控制 |
|------------|------|----------|
| 1 | 积分 + 抽奖次数 | 低 |
| 3 | 小礼品兑换券 / 必得低价礼（限库存） | 中，限前 N 名 |
| 5 | 更高权重抽奖 或 指定礼品 | 中高，严格限量 |
| 10 | 当期大奖池资格（含主题票/大礼） | 高，人工+风控 |

**禁止：**「邀请满 N 人无上限必送高客单奖品」。

### 4.3 分享设计

分享不是任务本身，是「结果放大器」：

- 中奖海报、连续签到海报、组队差 1 人海报、兑换成功海报  
- 双边激励：老用户得次数/积分，新用户得新手礼  
- 不强制分享才能用核心功能（合规与体验双红线）  
- 每个分享素材带 `channel_code + inviter_id + campaign_id`

### 4.4 裂变防刷

后台必须具备：

- 同设备多账号限制  
- 同 IP 高频限制  
- 互邀小圈子识别  
- 新用户质量分（次留、任务完成）  
- 异常邀请延迟结算 / 取消资格  

风控误伤要可申诉；但不能没有风控就开高价值邀请奖。

## 5. 激励与礼品机制（为转化与回流负责）

### 5.1 激励分层（成本漏斗）

| 层级 | 形态 | 综合成本目标 | 用途 |
|------|------|--------------|------|
| L0 | 积分、徽章、连续天数 | ≈0 | 每日反馈 |
| L1 | 抽奖次数、兑换加速 | ≈0 | 制造期待 |
| L2 | 阿里低价实物（到账综合成本控制在 3–12 元） | 低 | 主激励、晒单 |
| L3 | 主题大奖（如活动票、联名款） | 中高 | 限量话题钩子 |
| L4 | 现金红包/可提现 | — | **默认不做** |

### 5.2 礼品选品规则（1688 一件代发）

上架前必须算 **综合履约成本**：

```text
综合成本 = 采购价 + 代发运费 + 包材 + 支付费率 + 售后损耗预提 + 客服摊销
```

选品门槛：

- 目标用户喜欢（颜值、实用、可送人、适合晒图）  
- 综合成本可控，优先 1–10 元采购价，但以综合成本决策  
- 供应商稳定、可一件代发、退换规则清晰  
- 「免费礼」若需运费，**参与前**显著告知  
- 每月测款：转化高、投诉低的留下；其余淘汰  

礼品同时服务两条链路：

1. **激励链路**：抽奖/兑换消耗积分  
2. **商城链路**：同款或相近款现金+积分售卖  

### 5.3 抽奖机制

推荐「次数制抽选」，不做虚假概率噱头：

- 用户通过任务/邀请获得抽奖次数  
- 奖池公示：奖品、数量、规则、开奖/即时开奖方式  
- 保底：连续未中可提高低级奖概率或赠积分（防弃玩）  
- 大奖限量、中奖名单可查  
- 每人每日抽奖次数有上限  

库存扣减必须事务化；超发等于经营事故。

### 5.4 兑换机制

- 纯积分兑：仅限低成本/电子权益，或限量实物  
- 积分+现金兑：主力（用户付运费或差价，平台控毛利）  
- 每人每月兑实物次数上限  
- 兑换成功强制走地址确认与物流状态

## 6. 积分经济（活力值）

### 6.1 积分属性（不可破）

- 名称统一（建议继续用「活力值」或更中性名称，全站唯一）  
- **不可充值、不可提现、不可转赠、不可交易**  
- 不承诺固定现金汇率  
- 仅服务端记账，全量流水，幂等键  
- 支持冻结 / 解冻 / 过期 / 退回  

### 6.2 发放与消耗平衡

每月盯住：

| 指标 | 健康区间（初期建议） |
|------|----------------------|
| 消耗量 / 发放量 | ≥ 50% |
| 单 DAU 日均激励综合成本 | 尽量 ≤ 0.05–0.15 元（视收入调节） |
| 积分相关总成本 /（商城毛利+广告净收入+赞助） | ≤ 30% |
| 60 天内有过消耗行为的活跃用户占比 | ≥ 30% |

通胀信号：余额狂涨、兑换率下降、没人下单只等白嫖。  
通缩信号：分太难赚、任务没人做、DAU 掉。  

两端都要靠后台调任务分值与兑礼门槛，而不是发版。

### 6.3 商城：现金 + 积分怎么结合

三种货：

| 类型 | 支付 | 作用 |
|------|------|------|
| 纯积分货 | 100% 积分 | 消耗积分、低成本激励 |
| 现金+积分货 | 现金为主，积分抵 5%–10% | **主力利润货** |
| 纯现金货 | 现金 | 高毛利/联名/刚需 |

原则：

- 普通商品积分抵扣默认 **售价 5%–10%**  
- 运费谨慎抵扣；「免运」必须算进综合成本  
- 下单前试算接口给出：现金、积分、优惠、运费  
- 退款：退现金 + 退未过期积分；积分不折现  

商城选品 = 目标用户喜欢的低客单好物（饰品、数码小件、美妆小样、生活实用、主题周边等），**随用户群迭代，不绑定文旅。**

## 7. 变现与回本（为利润负责）

### 7.1 收入优先级

1. **商城毛利**（最早验证）  
2. **IAA**（激励视频、信息流；有 DAU 后放大）  
3. **品牌/商家付费**（奖池冠名、任务植入、曝光）  
4. **主题活动合作费**（谁用这台机器获客谁付费）  
5. 会员等后置能力（价值未立住前不收智商税）  

### 7.2 单位经济（每个运营动作先算账）

```text
单次有效激励成本 ≤ 该用户预期 30 日贡献毛利 × 安全系数(0.3–0.5)
```

```text
贡献毛利 =
  商城毛利 + 广告净收入 + 品牌/活动费
  − 礼品综合成本 − 运费补贴 − 支付手续费 − 售后 − 投流
```

没有单位经济表，不允许上线新的高价值奖励。

### 7.3 回本路径（阶段）

| 阶段 | 重点 | 成功标准 |
|------|------|----------|
| 机制冷启动 | DAU、次留、任务完成、首次抽奖/兑换 | 次留 ≥ 25%–30% |
| 裂变验证 | K 因子、有效新增成本 | 有效新增成本 < 30 日贡献 |
| 变现验证 | 首单率、广告 ARPDAU、毛利 | 激励成本占比 ≤ 收入 40% 并下降 |
| 规模化 | 调任务与奖池、扩渠道 | 贡献毛利转正 |
| 多端复制 | 同一中台多壳 | 单端先打平再复制 |

## 8. 主题活动怎么「插拔」（汉服节只是例子）

主题活动在系统里只是一个 `campaign`：

| 字段 | 作用 |
|------|------|
| 主题名/皮肤 | 海报、文案、首页背景 |
| 奖池 | 可放入当期特殊奖（含门票类限量奖） |
| 任务子集 | 可加几条主题任务 |
| 渠道码 | 单独算 ROI |
| 起止时间 | 到期自动下线 |

规则：

- 主题奖可以强，但 **常驻机制不能依赖主题奖**  
- 主题结束后，用户仍能签到、组队、抽日常礼、逛商城  
- 主题 ROI 单独结算；亏在主题、赚在沉淀用户，要算 30/90 日贡献  

当前汉服节若可用：把它配置成 Campaign #1。  
若下周结束：下线皮肤与大奖池，机制继续转。

## 9. 引流（为新增质量负责）

### 9.1 渠道原则

- 所有入口必须带渠道参数  
- 投流只优化 **有效新增成本** 与 **次留**，不优化裸量  
- 内容平台（抖音/小红书等）跑「任务得礼/组队打卡」素材，不绑定单一行业话术  
- 私域群按城市或兴趣建，承接中奖、组队、复购，不靠个人微信号硬广  

### 9.2 必备归因字段

`platform` / `channel_code` / `campaign_id` / `promoter_id` / `inviter_id`  
从落地 → 注册 → 激活 → 次留 → 兑换 → 下单 → 收入成本，全链路打通。

## 10. 产品研发路线（围绕机制，不围绕行业）

### V0.9 增长引擎最小闭环（优先）

- 首页（进度、任务、抽奖、邀请）  
- 签到 + 任务领取  
- 积分账户与流水  
- 邀请绑定与进度  
- 抽奖/兑换（含库存）  
- 礼品地址与履约状态  
- 渠道归因  
- 基础风控  
- 运营后台：任务、奖池、库存、渠道、开关  

### V1.0 留存与队伍

- 7 日循环签到与新手任务  
- 组队/队伍周榜  
- 步数任务  
- 用户分层与召回消息  
- 数据看板：DAU、次留、K、兑换、成本  

### V1.5 变现

- 商城 SPU/SKU  
- 现金 + 积分下单、支付、退款  
- 一件代发对接  
- 激励广告（达门槛后）  
- 单位经济看板  

### V2.0 规模

- 多端壳 + 统一账号映射  
- 主题活动配置中心（换皮工厂）  
- 更完整风控与供应商结算  
- 品牌任务订单

### 11.1 后台模块（第一期）

1. 任务配置  
2. 积分规则与流水查询/调账  
3. 奖池与库存  
4. 抽奖与中奖公示

## 12. 需求评审闸门（不会再跑偏）

任何新需求上线前，产品必须回答：

1. 它提升的是 **DAU、传播率、转化率、贡献毛利** 中的哪一项？  
2. 预期提升多少？如何埋点验证？  
3. 增加多少激励成本？预算从哪来？  
4. 是否可后台配置？是否可快速关停？  
5. 是否引入提现、强制分享、无资质售票等红线？  
6. 主题下线后，这个功能是否仍有价值？  

答不清，需求不排期。

### 12.1 明确不做（红线）

- 无资质售票作为主业  
- 常态可提现红包  
- 强制分享才能用核心功能  
- 无风控的无限邀请大奖  
- 客户端写死奖励  
- 多套积分货币并行  
- 未验证单端就四端铺开  
- 只报注册/GMV、不报成本与留存

## 13. 每周经营节奏

每周固定会只看：

1. DAU、次留、7 留  
2. K 因子、有效新增成本  
3. 任务完成率、抽奖率、兑换率  
4. 积分发放/消耗比、激励成本占比  
5. 商城毛利、广告净收入  
6. 刷量与客诉  
7. 下周：加一个实验、停一个亏损动作、保一个主路径

## 14. 最终行动纲领（给全员）

1. **机制常驻，主题可换。**  
2. **打开有奖，奖要轻；传播有奖，奖要严；消费有利，利要真。**  
3. **礼品用低成本好物打穿激励，用同款逻辑打穿商城。**  
4. **积分是燃料不是货币。**  
5. **所有研发服务于 DAU、传播率、转化率、贡献毛利。**  
6. **后台可配置、可计量、可关停，先于华丽功能。**
